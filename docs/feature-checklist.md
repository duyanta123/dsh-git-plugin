## 用户原始清单（1–54）

### 一、变更感知（看清楚改了什么）
1. 工作区状态识别：修改 / 新增 / 删除 / 重命名 / 未跟踪 / 冲突
2. 文件级 diff 查看（行级高亮、新增删除标记）
3. 暂存区 diff（看清楚"已暂存将要提交什么"）
4. 按文件 / 目录分组展示
5. 忽略文件（.gitignore）与未跟踪文件区分
6. 冲突文件检测与冲突标记
7. 多仓库支持（一个工作区里有多个 git 根目录）
8. 非 git 目录的初始化（git init）引导

### 二、暂存与撤销
9. 文件级 stage / unstage
10. Hunk 级 / 行级 stage（一个文件里只提交部分改动）
11. 部分提交（只提交已暂存内容）
12. discard：撤销工作区改动（还原文件，带确认）
13. 冲突三方解决（保留双方 / 手动编辑）
14. stash：暂存、查看列表、弹出、删除

### 三、提交
15. 提交信息编辑
16. AI 自动生成提交信息
17. Conventional Commits 规范（feat/fix/...）与校验
18. 作者署名 trailer（如 Co-authored-by / Generated-by）
19. amend：修订上一次提交
20. pre-commit hook 处理（执行、超时、失败提示、可跳过）
21. 提交护栏：密钥 /.env/ 大文件 / 构建产物拦截
22. 提交前 secret 扫描（防泄漏令牌）

### 四、分支与同步
23. 分支列表、新建、切换、删除
24. ahead /behind 计数（领先 / 落后远程多少）
25. fetch / pull / push
26. 首次推送自动 set-upstream
27. force push（强保护，必须确认）
28. merge 分支合并
29. rebase 变基（含冲突处理）
30. tag 标签管理

### 五、历史与可视化
31. Commit Graph 彩色分支图
32. 提交详情（完整 message、作者、时间）
33. 每个提交的文件变更对比
34. blame：逐行查看每行是谁、哪次提交改的
35. 历史搜索（按 message / 作者 / 文件）
36. 分支对比（两个分支差了哪些提交）
37. cherry-pick /revert/reset（软 / 混合 / 硬）
38. 虚拟 "未提交改动" 节点

### 六、Agent 专属（核心差异化）
39. 检查点 / 回滚：每轮或每任务前快照，一键回到任意点
40. 变更归因：区分 "agent 改的" 与 "用户手动改的"
41. 按会话 / 任务聚合改动
42. 自动提交模式：任务完成后自动 commit（可开关）
43. 任务自动开分支：新任务 fork 独立分支
44. 危险操作审批：push /force-push/reset --hard /clean 走确认
45. Agent 工具接口：白名单 git 操作，禁止模型自己拼 shell 命令
46. AI 生成 PR 描述、一键创建 PR

### 七、体验与工程
47. 右上角悬浮入口 + 变更角标
48. 提交 / 推送按钮（提交、提交并推送、同步三动作）
49. git 操作的可读错误提示（冲突、无远程、认证失败等）
50. 操作可撤销 / 二次确认
51. 快捷键与命令面板入口
52. 自动刷新（文件监听 + git 操作后刷新）
53. 暗色主题与国际化
54. 无 git 环境 / 无凭证的友好提示

## 复核补充建议（55–67，待并入分期）

55. **提交前 git 身份检查**：user.name/user.email 未配置时提交前提示（Windows 新机最常见报错）
56. **行尾与编码安全**：CRLF/autocrlf 行为提示；中文路径与文件名全程正确处理（报告风险章已点）
57. **多 remote 管理**：remote 列表查看与 push 目标选择（上个会话指出 push 失败路径要覆盖多 remote）
58. **手动/定时 fetch 与 behind 刷新**：fetch 的凭证失败给可读提示（24 的数据来源）
59. **二进制与大文件 diff 友好处理**：不渲染文本 diff、给占位与大小上限（numstat 二进制标记）
60. **单文件历史**：`git log -p --follow <path>` 的文件版本时间线（34 的补充）
61. **submodule/gitlink 状态展示**：只显示状态不递归（报告测试矩阵含 submodule）
62. **worktree 列表展示**：只读（对齐 opencode 的 worktree list --porcelain）
63. **hook 输出面板**：pre-commit 等 hook 的 stdout/stderr 展示区（20 的呈现层）
64. **空仓库/首次提交完整流程**：无 HEAD 时的 status/commit 特殊路径（报告已有 `git rm --cached` 兜底方案，显式列入需求）
65. **detached HEAD 状态显示**：header 与图中的明确提示
66. **写操作审计日志**：每个写操作记录可观测事件（对齐 dsh 的观测体系），便于排查
67. **推送前 diverged 检测**：push 前检测本地/远程分叉并引导（49 的具体化）

## 与 dsh 既有能力的对齐注意点（防重复建设）

- **39/40/41（检查点/归因/任务聚合）**：dsh 自带 `workspace-changes` 已做 turn 级快照与"本次会话改了什么"的归因（报告 4.2/4.4）。原则：**消费它的事件/数据做 UI 呈现，不重建快照引擎**；本插件管"真实仓库状态与提交"。
- **45（Agent 工具接口）**：dsh 有完整 tools 体系（tool-catalog、ctx.tools.guard）。把白名单 git 操作注册为真正的 agent tools 是本插件最亮的差异点，也是新增扩展面——需要阶段一读者核实 tools 注册契约。
- **46（PR）**：本机 gh CLI 已认证可用，PR 创建可走 `gh api`；AI 描述走 prepareCall。
- **42/43（自动提交/自动开分支）**：依赖 dsh 会话/任务事件契约，需要阶段一核实事件面。
- **13/29（三方冲突解决/rebase 冲突处理）**：全生态最难的两块 UI，建议最后做或不做。
